# AGENTS.md — apisdkopti24-examples

Правила для ИИ-агентов, работающих в этом репозитории. Основа — набор FAB's
AGENT.MD (правила чистого кода для ИИ-агентов), адаптированный под Python и под
работу с API топливных карт ОПТИ 24.

## Проект

- Портал примеров использования SDK [apisdkopti24](https://pypi.org/project/apisdkopti24/):
  дашборд с показателями и аналитикой, оповещения, выгрузки.
- Данные из API получаются только через `apisdkopti24` (версия не ниже 0.0.4).
  Собственных HTTP-клиентов к API ОПТИ 24 не писать.
- Документация и тексты интерфейса — на русском.

## Общение

- В комментариях, сообщениях коммитов и ответах — как можно меньше слов. Каждое
  слово выбирать тщательно. Меньше — лучше.
- Без похвал и превосходных степеней. Не писать «вы абсолютно правы». Только
  факты, даже неприятные.

## Код

- Магические числа и строки выносить в именованные константы или `Enum`.
  Очевидные одноразовые значения оставлять на месте. Значения из спецификаций —
  всегда константой (`http.HTTPStatus.OK`, а не `200`).
- Уменьшать вложенность: ранний `return` и `continue` вместо «стрелки» из
  вложенных `if`.
- Имена функций — короче 30 символов.
- `Enum` вместо булевых параметров функций.
- Пустая строка между логическими блоками кода.
- Перед блоком — короткий комментарий: что делает и зачем, с примером, если он
  помогает. Целые системы объяснять ASCII-схемой.
- Python: тело `if`, `for`, `while` — всегда на отдельной строке, даже из одной
  инструкции. JS/TS: всегда `{}`, даже у однострочного `if`.
- Python: аннотации типов везде, совместимость с `mypy --strict`.

## Архитектура

- Всё приватно по умолчанию (`_имя`, явный `__all__`). Расширение видимости —
  изменение дизайна: перед тем как сделать приватное публичным, спросить
  пользователя.
- Низкоуровневые детали — за отдельным слоем. Вызовы SDK, работа с БД и
  внешними каналами (Telegram, почта) живут в своих адаптерах; остальной код
  работает с понятиями предметной области: карта, транзакция, лимит.
- Строгие слои, каждый обращается только к соседнему нижнему:

  ```text
  интерфейс (дашборд, бот) → сервисы аналитики → хранилище
                                                 ↑
                              синхронизация → адаптер SDK → API ОПТИ 24
  ```

  Интерфейс никогда не вызывает SDK, API или SQL напрямую.

## API ОПТИ 24

- Интерфейс не обращается к API при открытии страницы. Данные загружает фоновая
  синхронизация по расписанию в хранилище; дашборд читает только хранилище.
- Частота — 1 запрос/с (значение SDK по умолчанию; при 2 запросах/с сервер
  отвечает `509`). Не повышать без явного решения пользователя.
- Почти каждый вызов тарифицируется. Перед добавлением вызова оценить расход
  запросов в сутки и указать его в описании изменения.
- Транзакции запрашиваются за период не длиннее месяца. Большие объёмы — через
  заказ отчёта (`order_report` → `get_report_jobs` → `download_report_file_to`).
- Итераторы SDK вызывать с `strict=True`: неполную выгрузку нельзя принимать за
  полную.
- Изменяющие вызовы (`set_limit`, `block_card`, переводы, выпуск карт) — только
  после явного подтверждения пользователя, с записью в журнал. Не повторять их
  автоматически после сетевого сбоя: сначала проверить состояние чтением.
- DEMO поддерживает не все методы и не доказывает работу на рабочем API.

## Данные и безопасность

- Ключ API, логин и пароль — только в переменных окружения сервера. `.env` не
  коммитить; образец — `.env.example` без значений.
- Номера карт, данные водителей, ID и номера договоров — персональные и
  коммерческие данные. Не выводить в журналы, исключения и публичный интерфейс;
  в интерфейсе маскировать (`**** 1234`).
- Публичная демо-версия и тесты работают только на синтетических данных. Реальные
  идентификаторы в репозиторий не попадают.

## Изменения

- Не трогать код, не связанный с задачей. Не добавлять комментарии к блокам,
  которые не создавались и не менялись в этой задаче.
- Минимизировать число изменённых строк.

## Тесты

- Исправление ошибки: сначала тест, который воспроизводит ошибку и падает; затем
  исправление; затем убедиться, что тест проходит.
- Тесты не обращаются к реальному API: синтетические данные и подставной
  транспорт (`httpx.MockTransport`).

## Коммиты

1. Заголовок отделён от тела одной пустой строкой.
2. Заголовок — до 50 символов (жёсткий предел 72).
3. Заголовок начинается с заглавной буквы.
4. В конце заголовка нет точки.
5. Заголовок в повелительном наклонении: «Add sync worker», а не «Added» или
   «Adds». Проверка: фраза «If applied, this commit will <заголовок>» читается
   правильно.
6. Тело переносится вручную на 72 символах.
7. Тело объясняет что и почему, а не как: как — видно из кода, сообщение даёт
   контекст и причины.

Коммит и push выполнять только по явной просьбе пользователя.
